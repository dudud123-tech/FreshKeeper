# 성장 레벨 시스템 설계

오늘까지야의 성장 레벨은 사용자가 앱을 자주 열고, 상품을 등록하고, 소비기한 전에 처리하는 행동을 자연스럽게 보상하기 위한 장기 시스템이다.

핵심 목표는 사용자가 단순히 유통기한을 관리하는 것이 아니라, "내 냉장고를 잘 돌보고 있다"는 성취감을 느끼도록 만드는 것이다.

## 기본 컨셉

- 상품을 등록하면 냉장고 관리가 시작된 것으로 보고 경험치를 준다.
- 상품을 소비기한 전에 완료 처리하면 더 큰 경험치를 준다.
- 임박 상품을 놓치기 전에 완료하면 추가 보상을 준다.
- 만료 상품이 생기면 경험치가 감소할 수 있다.
- 만료 상품을 정리하면 일부 경험치를 회복할 수 있다.
- 레벨은 1단계부터 10단계까지 사용한다.
- 레벨에 따라 `assets/Level/season1`의 캐릭터 이미지를 변경한다.

## 대시보드 문구 방향

기존의 "이번 달 관리 성장"은 이번 달만 관리하는 기능처럼 보일 수 있으므로 장기 성장 느낌이 나는 문구를 사용한다.

추천 문구:

- 나의 냉장고 성장
- 냉장고 성장 기록
- 우리 집 냉장고 레벨
- 냉장고 돌봄 레벨

레벨 문구 예시:

- Lv.1 관리 새싹
- Lv.2 차근차근 관리 중
- Lv.3 조금씩 좋아지고 있어요
- Lv.4 냉장고 습관 형성 중
- Lv.5 안정적인 관리 중
- Lv.6 놓치기 전에 잘 챙겨요
- Lv.7 알뜰 냉장고
- Lv.8 식재료 관리 고수
- Lv.9 버림 없이 가까워졌어요
- Lv.10 냉장고 마스터

## 경험치 규칙

1차 기준은 단순하고 예측 가능하게 유지한다.

| 행동 | 경험치 |
| --- | ---: |
| 상품 1개 등록 | +5 XP |
| 한 번에 여러 개 등록 | 개수 x 5 XP |
| 1회 등록 보상 상한 | 최대 +30 XP |
| 소비기한 전 완료 | 상품 1개당 +10 XP |
| 임박 상품 완료 | 상품 1개당 +15 XP |
| 만료 상품 발생 | 상품 1개당 -8 XP |
| 만료 상품 정리 | 상품 1개당 +3 XP |
| 하루 첫 방문 | +1 XP |

## 상품 등록 보상 기준

상품 등록은 "등록 횟수"가 아니라 "등록된 상품 개수" 기준으로 계산한다.

이유:

- 영수증 또는 구매내역 캡처로 한 번에 여러 상품을 등록할 수 있다.
- 1개 직접등록과 9개 OCR 등록을 같은 1회로 보면 보상이 너무 작다.
- 사용자가 실제로 관리 대상 상품을 많이 추가한 만큼 성취감을 주는 것이 좋다.

다만 OCR 오류나 대량 등록으로 경험치가 과하게 오르는 것을 막기 위해 1회 등록 보상은 최대 +30 XP로 제한한다.

예시:

| 등록 개수 | 지급 XP |
| ---: | ---: |
| 1개 | +5 XP |
| 3개 | +15 XP |
| 6개 | +30 XP |
| 9개 | +30 XP |

## 레벨 기준

초반에는 빠르게 성장하고, 뒤로 갈수록 천천히 성장하도록 설계한다.

| 레벨 | 필요 누적 XP |
| ---: | ---: |
| Lv.1 | 0 XP |
| Lv.2 | 30 XP |
| Lv.3 | 80 XP |
| Lv.4 | 150 XP |
| Lv.5 | 250 XP |
| Lv.6 | 380 XP |
| Lv.7 | 540 XP |
| Lv.8 | 730 XP |
| Lv.9 | 950 XP |
| Lv.10 | 1200 XP |

## 레벨 하락 기준

만료 상품이 생기면 경험치가 감소하고, 누적 XP가 현재 레벨 기준 아래로 내려가면 레벨도 내려갈 수 있다.

다만 사용자에게 벌점처럼 느껴지지 않도록 하락은 부드럽게 적용한다.

권장 제한:

- 하루 최대 감소 XP는 -10 XP까지만 적용한다.
- 레벨은 하루에 1단계 이상 떨어지지 않도록 한다.
- 만료 상품을 정리하면 일부 XP를 회복할 수 있게 한다.

## 표시 방식

대시보드 성장 카드는 월간 통계가 아니라 전체 성장 상태를 보여주는 영역으로 사용한다.

예시:

```text
나의 냉장고 성장

Lv.3 조금씩 좋아지고 있어요
이번 주 2개를 버리기 전에 챙겼어요.

다음 레벨까지 12 XP
[■■■■■□□□] 70%
```

보조 메시지는 최근 성과를 보여주되, 레벨 자체는 전체 누적 XP 기준으로 계산한다.

## 저장 데이터 예시

```js
growth: {
  xp: 85,
  level: 3,
  lastVisitDate: "2026-07-19",
  visitStreak: 4,
  totalRegistered: 34,
  totalCompletedBeforeExpiry: 12,
  totalExpired: 2
}
```

## 1차 구현 범위

- 대시보드 문구 변경
- 누적 XP 계산
- 상품 등록 시 XP 증가
- 완료 처리 시 XP 증가
- 만료 상품 수에 따라 XP 감소
- 레벨 이미지 1~10 자동 변경
- 다음 레벨까지 필요한 XP 표시

## 2차 구현 후보

- 연속 방문 보너스
- 주간 리포트
- 월간 리포트
- 레벨별 칭호
- 가족 공유 그룹 단위 성장
- 완료한 상품 기록 기반 뱃지

## 서버 저장 정책

성장 경험치는 로그인한 사용자만 서버에 저장한다.

- 비로그인 사용자는 기기 안의 상품 목록을 기준으로 대시보드에서 임시 계산한다.
- 로그인 사용자는 상품 등록, 소비기한 전 완료, 임박 상품 완료, 만료 발생을 성장 이벤트로 서버에 저장한다.
- 같은 상품으로 경험치를 반복해서 얻지 않도록 `event_key`를 기준으로 중복 저장을 막는다.
- 상품을 삭제해도 이미 발생한 성장 이벤트는 유지한다. 성장 기록은 사용자의 누적 관리 습관을 나타내기 때문이다.
- 계정 삭제 시 성장 이벤트도 함께 삭제한다.
- 가족 공유 상품의 완료 상태가 동기화되더라도 성장 경험치는 로그인 사용자 계정별로 따로 계산한다.

초기 구현은 다음 이벤트를 사용한다.

| 이벤트 | 서버 타입 | 경험치 |
| --- | --- | ---: |
| 상품 등록 | `register` | +5 XP |
| 소비기한 전 완료 | `complete` | +10 XP |
| 임박 상품 완료 | `complete_urgent` | +15 XP |
| 만료 발생 | `expired` | -8 XP |
