# 서버 상품 분류 구조

OCR로 찾은 상품의 카테고리, 보관 방법, 기본 소비기한은 Cloudflare Worker와
D1에서 판정합니다. 모바일은 서버 결과를 표시하고 사용자가 최종 등록한 값을
피드백으로 전송합니다.

사용자가 제외한 OCR 후보 기억과 할인 행 중복 제거는
`mobile/docs/ocr-candidate-memory.md`를 참고합니다.

## 조회 우선순위

1. 현재 기기에서 같은 상품을 마지막으로 등록한 값
2. 전체 기기의 공용 합의값
3. 식품안전나라 기반 서버 상품 사전
4. 분류할 수 없을 때 `기타 / 냉장 / 7일`

상품명은 유니코드 정규화 후 공백과 특수문자를 제거하고 소문자로 변환합니다.
따라서 `동물복지 대란(30구)`와 `동물복지대란 30구`는 같은 상품 키로 조회됩니다.

## 공용 합의 기준

- 서로 다른 기기 3개 이상
- 카테고리 1위 선택 비율 60% 이상
- 선택된 카테고리 안에서 보관 방법 1위 비율 60% 이상
- 소비기한은 선택된 카테고리·보관 방법 표본의 중앙값
- 같은 기기가 같은 상품을 여러 번 등록해도 최신 선택 1건만 투표로 집계

## 모바일 동작

- 서버 조회 성공: 서버 판정값 표시
- 서버 장애 또는 시간 초과: 기기에 캐시된 최근 판정값 사용
- 캐시도 없음: 사용자가 수정 가능한 중립 기본값 표시
- 사용자가 등록하면 최종 선택값을 서버에 전송하고 기기 캐시도 갱신
- 사용자가 제외한 OCR 후보는 기기별 제외 목록에 즉시 저장
- 다음 OCR에서는 서버 제외 목록과 기기 캐시를 확인해 해당 후보를 표시하지 않음

분류 서버 요청 제한 시간은 6초입니다. 네트워크 문제로 분류하지 못해도 상품
등록 자체는 막지 않습니다.

## 로그인 확장

현재는 앱 설치별 익명 `clientId`를 사용합니다. D1 스키마에는 계정 연결용
`account_id`가 준비되어 있지만, 클라이언트가 임의로 보낸 계정 ID는 신뢰하지
않습니다. 로그인 기능을 추가할 때 서버가 검증한 인증 토큰의 계정 ID만
`account_id`에 연결해야 합니다.

로그인 도입 후에도 조회 우선순위는 `계정 개인값 → 공용 합의값 → 상품 사전`을
유지합니다.
